# English Locale (EN) - Design

**Status:** approved 2026-09-17
**Goal:** Сделать сайт оцениваемым для человека, не читающего украинский, без ущерба для украинской продакшен-версии.

## Context

Проект подаётся вместе с заявкой на академическую мобильность в британский университет. Комиссия получает две ссылки: живой сайт и репозиторий. Реальной англоязычной аудитории у сервиса нет и не планируется.

Из этого следуют два решения, определяющие весь дизайн:

1. **Английские страницы закрыты в `noindex, nofollow`.** Вторая языковая версия без спроса на живом сайте с украинским трафиком - это риск размывания выдачи ради нуля. Демо-ценность сохраняется полностью: страница открывается по ссылке, поиск её не индексирует.
2. **Украинская версия не меняется ни на один видимый символ.** Любая правка украинских шаблонов допустима только если она невидима пользователю (служебные атрибуты) и не меняет вывод.

## Scope

### В работе

Весь путь посетителя: шапка, главная, форма поиска, выдача рейсов, детали рейса, удобства, модальное окно заказа, страница брони по токену, FAQ, клиентские ошибки, футер.

### Остаётся украинским - осознанно

| Область | Причина |
|---|---|
| 12 SEO-страниц маршрутов | Существуют только ради украинской выдачи, английских аналогов не нужно |
| Ссылки на них из блока «Популярні напрямки» | См. ниже: на EN блок не ведёт на украинские страницы |
| Юридические документы | Обязательную силу имеет оригинал; в футере EN - пометка о языке |
| Telegram-уведомления, письма | Получатель - украиноязычный менеджер |
| Админка (`admin.html`, `stats.html`) | Внутренний инструмент |

Комиссия получает ссылку не только на сайт, но и на репозиторий. Комментарии в коде и проектная документация - на украинском и русском, и это нормально: переписывать их бессмысленно и рискованно. Роль входной точки для англоязычного читателя берёт на себя `README.md` на английском.

Содержание:

- Архитектура: прокси поверх API перевозчика, генерация статики на билде, схема потока бронирования
- Инженерные решения, которые стоит заметить: генерация SEO-страниц из данных, деградация при заблокированном localStorage, защита от ботов, кеширование поиска, телеметрия неизвестных кодов от поставщика
- Как запустить локально
- Честная пометка: комментарии в коде украинские, интерфейс двуязычный

README - не переведённый маркетинговый текст, а техническое описание для читателя, который оценивает инженерную работу. Пишется один раз, поддержки не требует.

### Не трогать никогда

Код, который **разбирает** украинский текст из API, а не показывает его:

- `isGroupPrepay()` - `/груп/i.test(rt.price_label)`
- `groupThreshold()` - разбор `'двох'`, `'трьох'`, `'чотирьох'`, `'пяти'`, `'шести'`

Это парсинг данных поставщика. Перевод этих литералов сломает логику групповых скидок на продакшене.

## Architecture

### URL layout

```
/                → public/index.html        uk, без изменений
/faq             → public/faq.html          uk
/kyiv-varshava   → SEO-страницы маршрутов   uk, EN-версий нет
/t/:token        → public/booking.html      uk

/en/             → public/en/index.html     en, noindex
/en/faq          → public/en/faq.html       en, noindex
/en/t/:token     → public/en/booking.html   en, noindex
```

Английские страницы генерируются **на билде** в `public/en/`, тем же механизмом, что уже собирает страницы маршрутов и юридические документы. Никакой подмены текста в рантайме: нет мигания контента, нет задержки, нет зависимости от JS.

Каждая EN-страница получает `<html lang="en">`, `<meta name="robots" content="noindex, nofollow">` и отсутствует в `sitemap.xml`. Тег `canonical` на EN-страницах не ставится: с `noindex` он избыточен, а `canonical` на украинский аналог дал бы противоречивый сигнал.

### Popular destinations block

На украинской главной плитки блока «Популярні напрямки» ведут на SEO-страницы маршрутов. Английских версий этих страниц нет, поэтому на `/en/` плитки не навигируют, а **подставляют направление в форму поиска и запускают поиск на текущей странице**.

Посетитель получает то же самое - рейсы по популярному направлению в один клик - и не проваливается на украинскую страницу. Разметка блока общая, отличается только обработчик на EN.

### Dictionaries

Один источник правды на каждый вид данных:

```
i18n/en.json          интерфейс: ключ -> английская строка
i18n/cities-en.json   экзонимы: id города -> English name
i18n/geo-en.json      глоссарий служебных слов для адресов остановок
i18n/translit.js      транслитерация КМУ-2010
```

### HTML

Переводимые узлы помечаются атрибутами в украинских шаблонах:

- `data-i18n="hero.title"` - текстовое содержимое элемента
- `data-i18n-attr="placeholder:search.from;aria-label:search.fromAria"` - атрибуты

Украинская сборка атрибуты игнорирует и выводит украинский текст как есть. Английская подставляет строку из `en.json`.

Альтернатива - замена украинских фраз поиском по сырому HTML - отвергнута: она цепляет текст внутри атрибутов, JSON-LD и инлайновых скриптов, и промахи происходят молча.

### Client JavaScript

`app.js` общий для обеих версий. Украинские строки переезжают в словарь `T` в начале файла, обращения становятся `T.searching` вместо литерала. Английские страницы подгружают файл-оверрайд перед `app.js`; для украинских посетителей размер бандла не меняется.

**Порядок работ здесь критичен.** Сначала отдельным коммитом - чистый рефакторинг без английского: литералы уезжают в `T`, поведение украинской версии проверяется как неизменное. Только потом добавляется второй язык. Это самая объёмная часть (около 150 строк в живой воронке продаж) и единственная с реальным риском регрессии.

### Plurals and dates

В украинском три формы множественного числа (`рейс` / `рейси` / `рейсів`), в английском две. Существующие частные функции (`routeWord()` и аналогичные) обобщаются в один `plural(n, forms)`, форма выбирается по правилу текущего языка.

Названия месяцев и дней недели переезжают в словарь (`DOW`, `MON_SHORT`, `UA_MONTHS`).

## API data translation

Свободный текст из API «Контрабас» приходит на украинском. Три уровня обработки по типу данных:

### Уровень 1 - точный словарь

| Данные | Механизм |
|---|---|
| Города | `cities-en.json`, ключ - числовой `id` |
| Удобства | Существующая карта `AMENITIES` (коды уже локальные) |
| Ценовые метки (`price_label`) | См. уровень 3: разбор по шаблонам, непокрытая метка показывается с пометкой, а не скрывается |

**Словарь городов содержит только экзонимы** - случаи, где транслитерация даёт не то слово: Варшава → Warsaw, Краків → Krakow, Прага → Prague, Відень → Vienna, Мюнхен → Munich. Украинские города транслитерируются корректно сами (Київ → Kyiv, Львів → Lviv, Ужгород → Uzhhorod), записи для них не нужны. Ожидаемый объём - порядка семидесяти строк вместо двухсот.

**Инвариант:** в API всегда уходит числовой `id` города, никогда переведённое имя. Это уже так работает, менять не требуется, но нарушать нельзя.

### Уровень 2 - транслитерация с глоссарием

Адреса остановок (`departure_station`, `arrival_station`) - открытое множество. Один вокзал разные перевозчики пишут по-разному, с опечатками и дублями:

```
АС "Київ" вул., С. Петлюри, 32 ( 11-12 платформа)
Автостанція Київ (центральний залізничний вокзал), метро Вокзальна, вул. Симона Петлюри, буд. 32 Платформа 4 Платформа 4
```

Словарь точных строк промахнётся на первом же новом написании. Вместо него: глоссарий служебных слов (`Автостанція` / `АС` → Bus station, `вул.` → St., `метро` → metro, `платформа` → platform, `залізничний вокзал` → railway station) плюс транслитерация имён собственных по стандарту КМУ-2010 - тому, по которому оформляются загранпаспорта и уличные таблички.

Результат вида `Bus station "Kyiv", S. Petliury St., 32 (platform 11-12)` полезнее кириллицы: его можно прочесть вслух и найти в Google Maps.

### Уровень 3 - разбор по шаблонам

Поля, где транслитерация бесполезна (украинская фраза латиницей читателю ничего не даёт), но текст шаблонный. Замер на 326 реальных рейсах по четырём направлениям:

| Поле | Объём | Подход |
|---|---|---|
| `carrier` | 43 уникальных, 26 с кириллицей | Есть `/` и латинская часть - берём её как бренд (`TRANSTEMPO/ТрансТемпо` → `TRANSTEMPO`). Иначе транслитерация плюс словарь форм собственности: ТОВ → LLC, ТзОВ → LLC, ПП → sole proprietorship |
| `baggage` | 38 текстов, но 8 вариантов начала | Схемы вытаскивают числа (места, габариты, вес), английская фраза собирается из них |
| `change_info` | 21 уникальный | Схемы плюс словарь городов: «Пересадка у м. Львів» → `Transfer in Lviv` |
| `price_label` | 5 уникальных | Схемы. **Никогда не скрывать** - см. ниже |

**Первоначальное утверждение спека, что перевозчики приходят латиницей, было неверным.** Оно опиралось на локальную базу, где лежали только тестовые записи (`GRANDES TOUR`, `Pavluks-Trans`). В боевых данных больше половины названий кириллические.

### Запасной вариант, когда схема не подошла

Показываем исходный украинский текст с честной пометкой вида `Carrier's description (Ukrainian)`. Не скрываем и не транслитерируем.

**Ценовые метки скрывать нельзя ни при каких условиях.** Они несут условия оплаты: «Обов'язкова попередня оплата для груп з трьох і більше осіб». Спрятанная метка означает, что англоязычный пассажир считает бронь бесплатной и узнаёт правду у автобуса. Потеря денег и доверия хуже непереведённой строки.

### Где выполняется перевод

**На клиенте, в `app.js`, в момент отрисовки.** Сервер отдаёт данные API без изменений, одинаково для обеих версий.

Причина: ответы `/api/search` и `/api/cities` кешируются (поиск - 2 минуты, города - 30 минут в браузере). Перевод на сервере потребовал бы удвоить ключи кеша и протащить язык через весь путь запроса ради данных, которые всё равно рисует клиент.

Следствие: словари уровней 1 и 2 собираются в тот же файл-оверрайд, что и строки интерфейса, и грузятся только на английских страницах. На украинских не загружается ни байта.

### Telemetry

Существующий механизм `reportUnknownAmenity()` расширяется на города: город без словарной записи, для которого транслитерация выглядит подозрительно, отправляет сигнал. Пробел в словаре становится заметен, а не превращается в тихую кириллицу на английской странице.

## Language switcher

Переключатель `UA / EN` в шапке, ведёт на страницу-двойник. Выбор запоминается в localStorage через существующую безопасную обёртку (см. `fix(storage)`: хранилище может быть заблокировано, прямой доступ бросает исключение).

**Автоматического редиректа по `Accept-Language` нет.** Он неожидан для пользователя, ломает прямые ссылки и вредит индексации украинской версии.

## Server changes

`server.js`: одна новая строка - маршрут `/en/t/:token` по образцу существующего `/t/:token`.

Остальное покрывает `express.static` с уже настроенным `extensions: ['html']`: `/en/faq` отдаёт `public/en/faq.html`, `/en/` отдаёт `public/en/index.html`.

Серверные сообщения об ошибках, доходящие до клиента, переводятся через компактный словарь. Язык передаётся query-параметром `?lang=en`; любое иное значение или его отсутствие означает украинский. Количество таких строк - порядка пятнадцати.

Параметр влияет только на текст сообщения об ошибке. Ключи кеша поиска и городов он не затрагивает - данные API от языка не зависят.

## Testing

| Проверка | Что ловит |
|---|---|
| В `public/en/*.html` нет ни одного символа кириллицы | Любую забытую строку, без ручного просмотра |
| Каждый ключ `data-i18n` существует в `en.json` | Опечатки в ключах |
| В `en.json` нет осиротевших ключей | Мусор после правок шаблонов |
| Украинская сборка байт-в-байт совпадает с предыдущей после рефакторинга `T` | Регрессию в живой воронке |
| Транслитерация: набор эталонных пар | Ошибки в таблице КМУ-2010 |
| Переключатель языка ведёт на существующий файл | Битые ссылки между версиями |

Тесты добавляются в существующий `tests/smoke.test.js` или соседний файл, запуск - штатный `npm test`.

## Risks

| Риск | Смягчение |
|---|---|
| Регрессия в воронке продаж при рефакторинге `app.js` | Рефакторинг отдельным коммитом до добавления английского; проверка неизменности украинского вывода |
| Пропущенные строки в EN | Автоматическая проверка на кириллицу в сборке |
| Новый город без словарной записи | Транслитерация как запасной вариант плюс телеметрия |
| Рост стоимости поддержки текстов | Английский не покрывает SEO-страницы, юридические документы и уведомления - двойной поддержки там не возникает |

## Out of scope

Полная локализация (Telegram, письма, админка, юридические документы, SEO-страницы маршрутов, hreflang) не окупается при отсутствии англоязычной аудитории и создаёт постоянный долг на поддержку двух версий каждого текста.
